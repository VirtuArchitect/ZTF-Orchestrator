ZTF-Orchestrator v1.8.5-rc1
Release candidate - controlled UAT only

Scope
-----
Stabilization of the changes merged since v1.8.4. No new deployment-engine
architecture is included. Updated source builds add optional, administrator-approved
appliance update execution through a separately installed host service; unattended
release installation remains disabled.

Included changes
----------------
- Guided appliance ZIP updates: space and active-job checks, selected cleanup,
  verified backups excluding reproducible caches, exact-version approval, durable
  host progress and explicit compatible-image rollback. Requires one-time host
  service installation; existing CLI staging remains available. No release promotion.
- Versioned offline packages include the host-service bootstrap installer and
  configuration-preserving Compose preparation, with independent artifact hashes.
- Streamlined Overview with four operator tasks, recorded attention/activity and
  recovery preparation, plus a read-only saved-cluster-profile view. Advanced,
  optional-integration and administration groups retain existing routes and data.
  Previous dashboard panels remain expandable. No approval or execution changes.
- Updated source recovery flow permits only approved password/EULA/Pulse bootstrap
  before PE health verification, followed by strict read-only PE API evidence and
  health-gated remaining configuration. Exact approvals/confirmations and no-replay
  handling remain. Missing API evidence stays unknown; independent attestation is
  available after bootstrap. No live recovery validation or release promotion implied.
- Illustrated Disaster Recovery setup supplement: datacenter creation, Foundation
  VM deployment YAML and post-configuration pipeline links, reviewed baseline and
  verification without deployment. Generic simulated screenshots, PDF/Word copies,
  provenance and checksums. Documentation only; release channels remain unchanged.
- Source implementation of Disaster Recovery: datacenters, versioned Foundation
  VM cluster baselines, immutable run snapshots, governed rebuild submissions,
  sequential post-configuration jobs and explicit health/acceptance evidence.
  Rehearsals execute real changes. Restarts require reconciliation, never replay.
  Single application process coordination; representative physical recovery
  rehearsal remains required. See docs/disaster-recovery.md. No release promotion.
- Refreshed administrator/user Word manual, current simulated screenshots and
  aligned operator guides covering Start Here, PE diagnostics, persistent trust
  and Docker identity. Documentation refresh only; release channels are unchanged.
- Static demo build/appliance metadata now follows the frontend release version;
  its simulated build identity remains explicitly distinct from a live appliance.
- Start Here: four operator starting choices, seven-stage deployment guidance,
  post-configuration pipeline handoff, per-user browser landing preference and
  saved guide position. Existing role/approval/verification gates remain.
  Guide bookmarks never execute workflows. See docs/start-here.md.
- Updated source builds use a versioned local Compose image, forward build
  identity, and reject stale Docker version overrides before runtime installation.
  Local Compose deployment pins remain private and excluded from image contexts.
- Updated source builds report stage-specific PE local-user failures with safe
  credential, TLS, network, HTTP and verification categories. No secret values,
  response bodies or raw transport exceptions are included in these diagnostics.
- Updated source builds verify replacement PE admin authentication and stop
  unverified changes; unused password steps explicitly skip. Container readback
  verifies requested properties and rejects mismatches without auto-repair.
  Zero-exit verification failures stop subsequent pipeline steps.
- Updated source builds add Create Local Users (PE) to Scripts and pipelines:
  eight-user wizard, separate credential references, administrator-only exact
  confirmation, verified HTTPS and account/role verification. Live PE user
  creation remains an environment-specific UAT requirement.
- Updated source builds fail RegisterToPc FAIL/CAN'T VERIFY results even with
  exit code zero and expose redacted verification exception details.
- PostgreSQL 16 backup/restore clients match the bundled database; fresh builds
  no longer use newer dump tools that emit unsupported transaction_timeout.
- Operational Upgrade Advisor: verified-HTTPS PE/PC inventory, explicit unknown
  versions, saved assessments, readiness actions, and assessment exports.
- Viewer responses redact Prism endpoints in saved inventory observations/errors.
- Live PE DNS, NTP and Pulse drift reads on every scheduled run, plus editable
  schedules and UTC labels. Collection failures remain Unknown, not Matched.
- Initial PE password change in Scripts and pipelines, and Configure Cluster
  schema alignment for password references, EULA, Pulse and optional settings.
- Foundation VM image checksum preservation and native payload corrections;
  grouped classic Foundation progress with honest missing-telemetry states.
- Controlled-UAT CVM and Dell iDRAC password rotation safeguards, YAML Studio
  guidance, and Native Foundation readiness/adapter documentation.

Boundaries
----------
Not affiliated with or supported by Nutanix. A release-candidate label is not
production certification. PC product-header collection is not an authenticated
PC API permission check. NCC, LCM, firmware and Foundation versions still need
verified manual evidence where the bounded collector has no reader.
Credential rotation remains limited to its documented controlled-UAT scope.
Destructive Foundation/credential workflows need explicit target authorization.
No real cluster deployment or password rotation is implied by mocked tests.

Install and verify
------------------
Follow install-checklist-v1.8.5-rc1.md. Verify ZIP and embedded image checksums,
take independent backups, explicitly select v1.8.5-rc1, and retain rollback
images and the previous application/data backup pair. Do not replace latest.

Promotion
---------
The release is a prerelease, not the latest stable version. See
docs/releases/v1.8.5-rc1-readiness.md and the release validation receipt for
completed checks and outstanding live-UAT, recovery and soak gates.
