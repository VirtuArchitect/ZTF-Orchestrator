You need to build a four-node AHV cluster. Which Create Cluster workflow should you choose? Start with the deployment service available at the site. ZTF-Orchestrator offers three paths to the same goal, but each uses a different service and configuration.

Choose Cluster Create, Foundation VM, when you have a classic Foundation VM that can reach the physical nodes. This suits a local build, a remote site with its own Foundation VM, or an approved cluster rebuild. Review the node addresses and credential references, then select the approved images already in Foundation inventory. Refresh inventory, validate the payload, test IPMI credentials and check progress. The IPMI test uses the Orchestrator's network path; a failed direct test does not prove Foundation cannot reach the nodes. Follow Foundation's reported phase and percentage.

Now keep the same four-node requirement, but use Foundation Central associated with Prism Central. Choose the workflow named Cluster Create. It uses the existing ZTF one point x execution path. Configure the Foundation Central endpoint and credentials, then review eligible discovered nodes and the approved images. This is the appropriate choice when your deployment service and node inventory are already managed through that Foundation Central environment.

If your deployment service is a separate Foundation Central Appliance, choose Cluster Create, Standalone FCA. This path uses the appliance's Lifecycle APIs. Check the actual API version, inventory and hardware compatibility before proceeding. Submission remains guarded and requires the explicit execution acknowledgement. A workflow being available does not establish compatibility with every appliance or hardware version.

For each path, use its matching YAML schema. Do not swap configuration files between services. Run the checks available in that workflow, review the exact physical targets and obtain the required approval before imaging. Imaging can overwrite existing installations.

Monitor the submitted job and inspect the real outcome before retrying a failure. After cluster formation, verify Prism Element and continue with the reviewed post-configuration pipeline. Prism Central registration, when needed, is a separate configuration step.

For a broader site or multiple-cluster deployment, review Site Deploy or Site Deploy, Standalone FCA. Imaging Only prepares nodes without forming a cluster. For our four-node example, choose the Create Cluster workflow that matches the service you actually operate.
