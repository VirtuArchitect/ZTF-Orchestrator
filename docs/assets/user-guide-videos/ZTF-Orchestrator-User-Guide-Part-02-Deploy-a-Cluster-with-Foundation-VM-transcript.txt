Choose Deploy, then Foundation VM for a classic Foundation deployment. Enter the actual Foundation endpoint, not a future host or cluster address. Confirm that Foundation can reach the physical management, host and controller virtual machine networks. Keep its session separate from other deployments.

Refresh image inventory and select the exact approved AOS package already present. Typing a filename or choosing a local upload file does not stage it. If upload is required, wait for its result and refresh inventory. Supply the real hypervisor checksum and review every node identity, address and saved credential reference.

Refresh inventory, Validate native payload, Test IPMI credentials and Check progress have separate running and result feedback. Review each outcome rather than assuming the click passed. The IPMI panel reports per-node results and the test source. A direct Orchestrator routing failure does not prove Foundation cannot reach the controller.

Dry Run checks the reviewed intent without submitting imaging. Resolve schema, credential-reference, image and connectivity blockers. Have the required approver review the exact destructive scope. Imaging selected nodes can overwrite them; do not submit a new job just because the browser lost contact.

During an approved deployment, follow the existing job and actual Foundation phase and percentage. Missing telemetry remains Not reported. Check progress does not itself start imaging. Reconcile an interrupted session before another submission, then verify cluster membership, versions and services before handing off configuration.
