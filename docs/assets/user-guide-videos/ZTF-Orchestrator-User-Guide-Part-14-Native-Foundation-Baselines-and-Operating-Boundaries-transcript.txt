A planning screen can produce a manifest or readiness report without deploying anything. In the retained Foundation planning tools, inspect the returned read-only and execution-enabled flags. A count of passed checks is not a count of imaged nodes or proof of a completed cluster.

For Cluster A, inspect the node serials, addresses, image selections and credential references in the plan. Review each blocker and unsupported operation. Do not infer discovered hardware, an approved maintenance window or live authorization from a generated file.

When using classic Foundation VM, open its supported deployment workflow and review its own validation, approval and mutation gates. Foundation remains the imaging service. The separate retired Native pipeline option does not become available because another feature uses the word native.

A connectivity or credential probe establishes only the checks it performed from its stated source. It does not prove later reboot behavior, VLAN reachability or end-to-end imaging. Validate the selected hardware and software combination in an approved environment before enabling guarded live changes.

Retain the plan, approval, actual job output and target verification separately. Use actual Foundation telemetry during deployment and reconcile uncertain submissions before a new attempt. This lesson demonstrates those boundaries with simulated data and performs no imaging.
