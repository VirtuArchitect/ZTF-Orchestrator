Part 01 - Dashboard Overview
Updated 4 November 2026. Simulated console examples; synthetic narration.

Choose your starting point
If you want to deploy a cluster, start with Deploy a Cluster. You do not need to search through script names. Start Here offers four choices: deploy, configure an existing cluster, monitor and verify, or run saved automation. This series follows the current console with simulated examples. It does not execute changes against a real environment.

Read the operations overview
Open Overview for the daily operations view. The four action cards open deployment, configuration, infrastructure recovery and monitoring. These links do not execute work.

The summary now shows Managed clusters, Open review items, Running jobs and Fresh P E Good readbacks. Managed cluster counts come from explicitly registered records. They are not automatic discovery, and recovery profile counts remain a separate concept.

Read the timestamp and evidence below each record. Refresh reloads saved operational records. Merely opening or refreshing this page never contacts Prism Element.

Investigate persistent review items
Needs attention retains observed failed or interrupted jobs and P E observation issues. Open the original job or review the cluster before deciding what to do. A newer successful job does not erase an earlier failure record.

Choose Update review, assign an owner, and record useful reconciliation notes without secrets. Acknowledge the item while follow-up is in progress. Choose Resolved after review only after checking the actual outcome.

Acknowledgement and resolution update the review record. They do not fix the target, approve execution, change recovery gates or replay a job. A new failed P E readback can reopen a resolved observation item.

Manage cluster records and fresh observations
Open Clusters to add or edit an explicit managed record. Link its saved configuration files, pipeline and recovery profile, then enter the expected cluster identity, complete node baseline and credential reference. Importing expected membership from Foundation Y A M L does not discover the actual target.

Stale observation means the stored P E evidence is older than fifteen minutes or is unavailable as fresh evidence. It does not by itself mean the cluster is unhealthy. Select Review for the cluster, then Collect P E health, read-only, to request new evidence.

Collection requires expected U U I D, node baseline, a credential reference and trusted H T T P S. Missing or failed evidence stays unknown. P E reported health is narrower than N C C, resilience testing and application acceptance. Existing recovery profiles remain listed separately on Clusters.

Find the specialist tools
The streamlined sidebar keeps ordinary tasks visible. Expand Advanced Automation for workflows, scripts, configuration files, schedules and execution history. Optional Integrations contains the preview integration paths. Administration contains setup, credentials, appliance operations and settings. N K P Validation Evidence carries a Preview badge and retains its specialist sources. Use execution history and target readbacks for ordinary cluster verification.

Start safely and follow the evidence
For a normal task, choose the correct workflow, review the saved configuration, run the available dry run, obtain any required approval, and submit once. Follow its record in Jobs and Queue. Investigate failures before retrying. You can retain Start Here or Overview as your browser landing preference. Part two follows cluster deployment through the Foundation V M workflow.
