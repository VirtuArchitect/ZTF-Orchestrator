AHV Appliance Deployment and SSH Setup

Prepare the appliance
Verify the approved appliance image against its checksum. Import it as a disk in Prism, create the virtual machine, and connect its adapter to the management subnet. Keep the machine powered off while you prepare access.

Prepare access before boot
On Windows, generate an SSH key with the commands on screen. Copy the full public key line from the dot pub file. Keep the private key on your workstation. In guest customization, provision the Z T F admin account and add its public key. On a static-only network, arrange a Linux administrator login for the Prism console if you need to set the address there. The SSH key example leaves the console password unset. Keep SSH password authentication disabled.

Set the IP before SSH
Now power on. If you use DHCP, confirm the assigned address. If the subnet has no DHCP, verify the static address set by provisioning, or sign in through the Prism virtual machine console to set it. If you have no address and no working console login, ask the provisioning administrator to supply access before continuing.

Secure and test Netplan
For a console-configured static address, identify the correct interface and back up its Netplan file. Use the approved IP, prefix, gateway and DNS. If cloud-init owns the file, make the change at the provisioning source. Set ownership to root and permissions to six hundred on the file named in the warning. Run Netplan generate, then start the trial from the console. Keep that console open.

Verify SSH and sudo
Once the IP is active, connect as Z T F admin with the matching private key. Verify the server fingerprint before accepting it. At the Linux prompt, run who am I and sudo dash V. Expect the Z T F admin username and a successful sudo check. If you are testing a Netplan change, accept it from the console after verifying the route and SSH access. If the checks fail, let the trial expire and restore the backup.

Retrieve or reset the web password
Check that both containers are running and that the local health endpoint reports healthy. Search the service journal for the first-run password, then check Docker logs if the journal has no match. If both logs lack the banner and you have no current web credential, open the Quick Guide's password reset page. Run the full command from an interactive Linux session and enter a new password twice. If the admin account is missing, preserve the user store and contact the appliance maintainer.

Sign in and verify
Open the approved appliance address in your browser and sign in as admin. If you used the generated password, rotate it under Administration, Users. Confirm the installed build and record the management address and health result.
