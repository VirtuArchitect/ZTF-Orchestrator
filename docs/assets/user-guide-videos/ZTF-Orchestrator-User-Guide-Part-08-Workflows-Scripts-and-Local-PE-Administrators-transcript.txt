Part 08 - Workflows Scripts and Local PE Administrators
Updated 4 November 2026. Simulated console examples; synthetic narration.

Choose a workflow for the required backend
Expand Advanced Automation and open Workflows. Read the description and select the service actually available. Integrated Foundation Central, standalone F C A and classic Foundation V M use different contracts. Import or complete the matching form and review its generated configuration. Do not assume that a similarly named action has the same credentials or execution semantics.

Use scripts for focused actions
Open Scripts for a specific allowlisted action. Use its parameter wizard and installed schema, then review the generated input. A script sequence and a workflow are different launch modes. Supply the required saved file and inspect verification after execution.

Set Prism Login Title for P E is now available as a focused script or pipeline action, with title-only Configure Cluster support. Review the exact title and cluster, select the correct vault credential reference and retain certificate verification.

The action compares the existing setting, applies a change only when needed, and requires a fresh readback to verify the requested title. Legacy U I A P I compatibility still needs validation against the target A O S version. A saved title or subprocess success alone does not prove the target displays it.

Create named local PE administrators
For local P E users choose Create Local Users for P E. Each requested username needs its own matching credential reference. Select the intended role set explicitly and respect the installed schema. Run Dry Run before submission. After creation, independently confirm that each account is enabled and has both Cluster Admin and User Admin when those are the approved roles.

Read a stage-specific failure
Inspect the stage and safe category when local user creation fails. Credential resolution, certificate trust, identity mismatch, network access, creation, role assignment and verification are separate failure points. Check whether any accounts or roles were already created. Correct the actual cause and rerun only through the supported process. Do not paste passwords or raw authentication headers into a support request.

Treat credential rotation as a sensitive operation
The C V M and Dell i D R A C rotation workflow has a separate support boundary and exact confirmations. Verify each C V M host-key fingerprint independently, establish the required access and keep an out-of-band recovery path. Review any manual follow-up, including host I P M I credential synchronization. A dry run or approval does not prove that live rotation is validated for your firmware and release.
