For an appliance update, first check the installed build and the exact trusted package supplied by the maintainer. A source commit, update ZIP and running image are different states. Finish or reconcile active automation. Keep a verified database and data backup pair, the previous application image and a recovery method.

Open Appliance Ops, Updates, and Review Storage Before Upload. Several locations may share the same filesystem. Keep enough space for the package, image load and backup allowance. Use reviewed cleanup or the disk expansion guide if needed; do not delete Docker volumes or the only verified backup to force readiness.

Upload the complete offline ZIP and verify it, then select the imported package and Check Readiness. Import validates and stages content; it does not activate the image or execute a bundled host installer. If the host service is absent, follow the separate reviewed bootstrap instructions first.

After readiness passes, review and enter the exact version confirmation. Submit once. Completed stages are green, the current stage is distinct, and failures identify their stage. If the browser loses contact, recover the existing operation rather than starting another installation.

Verify the running image and health build identity, then check retained credentials, configurations, pipelines, approvals and recovery progress. If rollback is required, use the recorded previous image and matching verified backup pair through the documented recovery path. Appliance rollback does not undo target changes such as enabled encryption.
