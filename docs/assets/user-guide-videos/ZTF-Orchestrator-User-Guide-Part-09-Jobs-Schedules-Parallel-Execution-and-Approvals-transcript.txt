In Jobs and Queue, open the existing record for Cluster A. A pipeline with several Configure actions now identifies each saved configuration step. Review its reported stage, timestamps, return code, persisted output and diagnostics. A failed job shows the last reported or failed stage rather than a misleading completed estimate.

If no log events or node telemetry were recorded, that means evidence is unavailable. It does not prove that Foundation never started or that a later stage completed. Use the retained error and the actual target session to reconcile uncertain state. Do not infer success from an aggregate percentage alone.

The Approvals badge shows an amber pending count or a blue zero when none are pending. An unavailable count is not zero. Open the request and compare its target, exact intent and expiry. Sensitive specialist actions require another administrator; a changed plan needs renewed approval.

Test supported automation manually before creating a schedule. Parallel execution is appropriate only where the action and independent targets support it. It is not a shortcut for concurrent imaging sessions on one Foundation VM or for specialist actions that require their own guarded job path.

A cancellation request cannot undo an accepted remote command. Keep the original job and inspect the target before another submission. Recovery continuation preserves successful steps and approvals. Use its eligible pending-step path rather than restarting the entire pipeline to repair a final registration failure.
